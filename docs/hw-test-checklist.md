# 저녁 실기체 테스트 체크리스트

대상: Meteor75 Pro (O4, CRSF) · Pavo20 Pro2 (O4) · GEPRC Moz7 (O4 Pro, ELRS)
예상 소요: 기체당 10~15분
배경: [cli-compat.md](cli-compat.md) — 소스상 모든 버전에서 `'#'` 진입이 되어야 하고, 오늘 이것을 실기체로 처음 확인합니다.

> 이 앱은 FC에 아무것도 쓰지 않습니다(`#`, `version`, `status`, `diff all`, `dump all`, `get` 만 보냄). 그래도 테스트 중에는 **프로펠러를 빼고 배터리 없이 USB 전원으로만** 연결하세요.

## 0. 준비 (한 번만)

- [ ] 프로젝트 폴더에서 터미널을 열고 **개발 모드로 실행**합니다. 오류가 나면 터미널에 `[serial] ...` 줄이 찍히므로 로그로 쓸 수 있습니다.
  ```
  npm run dev
  ```
  exe로 하고 싶다면 `release\Betaflight-CLI-Editor-Portable-<버전>.exe`(v1은 `FC-CLI-Viewer-0.1.0-portable.exe`)를 써도 되지만, 이때는 오류 로그가 화면 메시지로만 남습니다.
- [ ] **Betaflight App(Configurator)을 닫습니다.** 열려 있으면 COM 포트를 잡고 있어 "다른 프로그램이 포트를 사용 중"이 뜹니다.
- [ ] 결과를 적을 표(맨 아래)를 띄워 둡니다.

## 1. 기체마다 할 일 (Meteor75 Pro → Pavo20 Pro2 → Moz7 순서)

### A. 연결과 읽기
1. [ ] 기체를 USB로 연결 → 앱 첫 화면 드롭다운에 **"(FC 추정)"** 포트가 맨 위에 나오는지 확인
   - 안 나오면: 새로고침(2초마다 자동 갱신) → 그래도 없으면 다른 USB 케이블 → 장치 관리자 "포트(COM & LPT)" 확인
2. [ ] **기체 연결** → 이름 입력 창이 뜨고, 기본값이 FC의 `craft_name`인지 확인 (비어 있을 수도 있음)
3. [ ] 이름 입력 → **읽기 시작** → 진행 표시에서 `version → status → diff all → dump all`이 차례로 끝나는지, **시간**(목표 30초 이내)을 기록
4. [ ] "읽기가 끝났습니다 … USB를 뽑았다 다시 꽂으세요" 안내가 뜨는지

### B. 화면 확인 (Betaflight App과 비교)
이 단계는 USB를 뽑았다 꽂은 뒤 **Betaflight App을 열어** 같은 기체를 연결하고 나란히 비교합니다. 이때 앱 쪽은 이미 읽은 화면이라 연결이 필요 없습니다.

5. [ ] **설정 탭**: 펌웨어 버전(예: `Betaflight 4.5.1` 또는 `2025.12.x`)을 결과표에 적기
6. [ ] **PID 튜닝 → PID 설정**: 활성 프로필의 P·I·D·피드포워드 값이 App과 같은지
   - 4.5.x면 표 머리가 **"D (최대)", "D Min (기본)"**, 2025.12.x면 **"D (기본)", "D Max (최대)"**(+ S 열)인지
   - App에서 바꾼 적 있는 값에 **노란 테두리**가 있는지
7. [ ] **PID 튜닝 → 레이트**: 레이트 방식과 RC 레이트/슈퍼 레이트/엑스포, 최대 속도(°/s)가 App과 같은지
8. [ ] **PID 튜닝 → 필터**: D-term 로우패스에 "동적 최소/최대" 값이 보이는지 (오늘 고친 부분)
9. [ ] **포트 탭**: UART별 MSP / Serial RX / 주변기기(VTX MSP + DisplayPort)가 App과 같은지
   - 2025.12.x면 행 이름 옆 작은 글씨가 `serial UART2`처럼 **이름**으로 나오는지
   - O4 연결 UART에 "VTX (MSP + DisplayPort)"가 표시되는지
10. [ ] **모드 탭**: ARM·ANGLE·FLIP OVER AFTER CRASH 등 모드와 AUX 채널·범위가 App과 같은지
11. [ ] **수신기 탭**: 프로토콜(CRSF/ELRS)이 맞는지
12. [ ] **OSD 탭**: 캔버스가 **53×20** 으로 나오고 ("53×20 (status)" 또는 "HD (53×20)") 미리보기 위치가 고글 화면과 대략 같은지
13. [ ] **기타 탭**: "해석 못 한 줄"이 **0줄**인지 (0이 아니면 그 줄을 결과표에 복사)
14. [ ] (Moz7) **GPS 탭**: GPS 기능 켜짐, 레스큐 값. 2025.12.x면 "오토파일럿" 패널이 있는지

### C. 저장과 다시 열기
15. [ ] **저장** → 기본 파일명이 `<기체이름>.bfview.json`이고 처음엔 `문서\FPV 기체` 폴더인지 → 저장
16. [ ] **원문 내보내기** → `<기체이름>_diff.txt` 저장
17. [ ] **처음으로** → **저장 파일 열기**로 방금 파일 열기 → 같은 화면, 상단 바에 "오프라인 파일 · 읽은 시각"

### D. 파서 테스트용 원문 받기 (Betaflight App에서)
18. [ ] Betaflight App → CLI 탭 → `diff all` 입력 → **Save to File** → `fixtures\<이름>.diff.txt`
19. [ ] 같은 방법으로 `dump all` → `fixtures\<이름>.dump.txt`
    - `<이름>`은 `meteor75-pro`, `pavo20-pro2`, `moz7`
    - 끝나면 App에서 연결 해제 (CLI에서 `exit`를 치면 4.5.4+는 재부팅합니다 — 괜찮지만 필요 없음)

## 2. 세 기체가 끝나면

- [ ] 프로젝트 폴더에서 실행 → 실제 덤프 테스트 결과를 확인
  ```
  npm test
  ```
  `실제 픽스처: meteor75-pro.dump.txt` 같은 항목이 통과하는지 보고, 실패하면 아래 "넘겨줄 것"에 출력 전체를 포함하세요.

## 실패했을 때 넘겨줄 것

| 어디서 실패 | 넘겨줄 것 |
| --- | --- |
| 포트가 안 보임 | 장치 관리자 "포트(COM & LPT)" 화면 캡처, 사용한 USB 케이블/허브 여부 |
| 기체 연결 단계 (CLI 진입 실패·포트 사용 중) | ① 앱의 빨간 오류 문구 캡처 ② `npm run dev` 터미널의 `[serial]` 줄 전체 ③ 그 기체의 펌웨어 버전(Betaflight App 첫 화면) ④ 그 직전에 Betaflight App을 썼는지 |
| 읽는 중 멈춤·시간 초과 | 위 ①②③ + 진행 표시에서 **어느 명령에서 몇 줄 받고** 멈췄는지 |
| 값이 App과 다름 | 해당 탭 캡처(앱과 App 둘 다) + `<이름>.bfview.json` + `fixtures\<이름>.diff.txt`·`.dump.txt` |
| 기타 탭에 해석 못 한 줄 | 그 줄들 복사 + `fixtures\<이름>.dump.txt` |
| 저장·열기 실패 | 오류 문구 캡처 + 저장하려던 폴더 경로 |
| `npm test` 실패 | 터미널 출력 전체 + 해당 `fixtures\*.txt` |

파일은 프로젝트 폴더 안에 그대로 두고 경로만 알려 주셔도 됩니다. `.bfview.json`에는 4개 명령의 원문이 모두 들어 있어서 그것만으로도 대부분 재현할 수 있습니다.

> 연결 디버그 로그(송수신 원문을 파일로 남기는 기능)는 아직 없습니다(4단계). 오늘 연결 단계에서 실패하면 그 결과를 보고 4단계에서 추가하겠습니다.
